# Request routing and automatic model escalation

Auto keeps ordinary conversation and short Q&A on the Phone model. Substantial planning, analysis, multi-step work, long requests, chat goals, and attachments over 6,000 characters use Deep. The existing Quick and Deep slot assignments take precedence. Without those assignments, Auto starts with the smallest suitable downloaded phone model for Quick and the largest for Deep. Explicit Quick/Deep modes and an explicitly selected Home model keep their existing override behavior. The existing optional Home assignment still handles eligible Deep analysis; Home does not acquire phone tools.

A detected model failure moves the same phone chat turn to the next larger suitable installed model, with at most three models attempted. Each path is tried once. Escalation uses Deep, updates the active model indicator and saved turn model, increments the existing attempt count, and logs the transition. It does not download models, change the user's slot assignments, create another user message, or send phone tool context to Home.

Ranking uses a parameter count in the model name or filename when available, including B and M units; otherwise file size is an approximate fallback. Quantization variants with the same parameter count are not separate size tiers. Available files and the existing phone memory suitability checks filter automatic choices. Size is a routing hint, not measured proof that one model will answer better; explicit slot choices remain useful.

Model failures include malformed action selection, unfinished replies, generation/context errors, and model-step timeouts. Inference steps are limited to two minutes in Quick and five minutes in Deep. Parent cancellation and Stop never start another model. Missing required user details produce a clarification. Pending or denied approval, tool/network failures, uncertain tool outcomes, and detected memory allocation failures do not move to a larger model.

The next model continues from confirmed tool results. The execution scope and write receipts stay attached to the same turn. The handoff restores discovered capabilities through app-owned menus, preserves the existing plan ID and approval restrictions, and carries executed call keys across attempts. An approved action that completed before a generation failure is not executed again. A repeated completed write is blocked before asking for another approval. Changed or additional proposed writes still use normal approval rules.

After a successful simple web lookup, Cina composes a final text answer with tools disabled. This prevents a model from starting an unrelated local task or repeating a lookup that already returned results. Complex research and requests with further actions retain their tool continuation. A failed final composition can still escalate using the saved search result, without performing the search again.

The handoff is automatic while the phone chat is running, including resuming an approved action. It does not add unattended execution after the app closes. Scheduled prompts retain their explicitly selected model, and Home jobs retain their own durable execution path. Incorrect but fluent answers cannot all be detected automatically; the ladder handles observable failures, not a general correctness judgment.

Validation covers size/complexity routing, configured slots, parameter versus file-size ordering, unsuitable and missing models, bounded attempts, cancellation versus timeout, clarification and approvals, network failures, and continuation after an approved write or successful search. The end-to-end Android tests use the production ViewModel/runtime/tools/storage with scripted inference so these failure scenarios are deterministic.

Validation completed: 98 JVM tests and 33 Android instrumentation tests passed, along with Android lint and the debug app/test builds. The Android suite includes eight ViewModel escalation scenarios, 23 protocol/recovery scenarios, the collection lookup through both real Qwen3 0.6B Q8_0 and 1.7B Q8_0 models, and a real-model grammar test proving that forced tool formatting can be explicitly cleared before an ordinary reply. Both native lookup cases issued an actual search with the city and street address, then returned the controlled collection day directly. See [native lookup evidence](model-routing-native-results-2026-10-25.txt).

Verification used a disposable emulator with the separate `.uxreview` application ID. These changes remain local and have not been released to the user's phone.
